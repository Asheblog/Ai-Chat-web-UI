# ADR-0047：设置对齐实际运行并保留全部回答版本

- 状态：接受
- 日期：2026-11-16

## 背景

设置审计发现重复配置、无消费者字段、显示默认值与运行值不同，以及回答版本裁剪连带删除历史用量。用户接受精简方案，并明确取消单条消息的回答数量上限。

## 决定

1. 全部回答版本及其历史用量保留。生成和切换继续使用原消息身份；只重排版本索引，不按数量删除。
2. 设置接口复用流式运行配置解析器，显式存量值继续生效。保存失败向调用方抛出错误，页面保留输入并反馈服务端原因。
3. 搜索启用集合与排序合为一个有序列表；双语只保留模式；删除无运行消费者的 Python 限制、provider idle 字段与固定融合策略。
4. 能力、生成参数、访问覆写分别保存与重置；聚合标记 manualOverride 不门控能力刷新。能力层序为人工覆写 > 供应商声明 > 模型名启发 > 连接默认。生成参数按模型和协议裁剪，思考强度默认 Auto；全局生成上限 0 表示自动，解析顺序为模型人工上限 > 已知模型表 > 显式系统值 > 协议自动值；已解析上限受剩余上下文约束。未解析到上限时，OpenAI 系省略 max_tokens，Anthropic 以保守 4096（并受剩余上下文约束）满足协议必填要求。
5. 知识库功能与角色策略在服务端执行，包括直接携带知识库 ID 的聊天检索；管理入口保留。
6. 图片、匿名会话和乱斗保留天数 0 表示永久保留。任务追踪保留阈值用于手动清理，系统日志临时设置在进程重启后回落部署值。
7. 设置按概览和六组组织，高级参数折叠。全局角色提示词归入连接与模型下的会话默认配置，个人提示词继续作为独立偏好层叠加。

## 迁移

服务启动先等待 SQLite 初始化，再以单事务合并旧引擎顺序和双语关闭状态，删除八个废弃设置键并写入一次性标记。后续启动不再读取旧排序和双语环境变量。无需删除聊天数据。旧连接类型停止承担产品语义，旧 session 认证需重新配置。

## 取舍

全部版本保留增加存储占用，换取历史可追溯与用量统计完整性。有效的传输保活参数保留在高级区；本轮不根据前端是否消费保活事件来删除传输行为。
