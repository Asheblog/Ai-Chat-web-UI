# 会话上下文开关归账号所有，并移除"新对话继承上下文"

"记住对话上下文"原本是前端 Zustand persist 落在 `localStorage` 的布尔值，只控制**当前会话历史**是否随请求发送；而同一张卡片里的"个人系统提示词"存在服务端 `users` 表。同一组设置两种存储模型，派生出四个症状：换设备失效、共用浏览器串账号（登出只清 `auth-storage`）、无痕模式重置、移动端硬编码 `true` 无法关闭。

决策：开关迁到 `users.contextEnabled`（默认 `true`），与个人提示词同源；服务端解析顺序为**请求显式值 → 账号偏好 → `true`**，收敛到单一函数 `resolveContextEnabled`，压缩门与请求构建共用同一结果。移动端不再传该字段，自动跟随账号。

同一张卡片里的"新对话继承上下文"自 2026-04-26 引入以来**没有任何读取方**（全仓 8 处引用都是写入侧），且语义无法定义：继承几条、多久衰减、跨会话隐私边界都没有答案。它描述的是"跨会话长期记忆"的中间态，而 `app-info` 的 `features.long_term_memory` 一直是 `false`。故直接删除，不实现。

同时明确"关闭上下文"不等于"临时对话"：消息照常入库，只是不进入本次请求，重新开启即可继续。UI 文案改为陈述这一事实，不再暗示跨会话记忆。
