# 网页正文获取改造方案

状态：已接受，实施分支 improve-web-retrieval。目标是取得更多有效正文、减少无效请求与等待，让已恢复的内部尝试不再重复显示为失败。用户要求按流程实施、合并主分支并推送；新增约束为服务器资源有限，必须限制浏览器资源。

## 推荐选择

采用统一网页读取模块：复用搜索正文 → HTTP 与多种正文提取器 → 按需浏览器渲染 → 已配置的提取服务 → 明确标记的降级结果。Node 负责网络、总截止线、取消、文档和浏览器；Python 用 Trafilatura 补充正文与表格提取，处理已经下载的 HTML。

先修已复现的误判和流程缺陷，再增加提取器。沿用现有搜索适配、Playwright Chromium、Python 环境管理和单镜像部署，不新增 Redis、Celery、Scrapy 等平台依赖。

## 证据决定的优先级

| 当前行为 | 影响 | 处理 |
| --- | --- | --- |
| 正常文章提到 Cloudflare / CAPTCHA 被判挑战页 | 可读正文被误丢弃 | 挑战页结构、响应特征与正文可得性组合判定，关键词只辅助 |
| 缺 Content-Type 时跳过响应体 | 未解析便失败 | 受限读取前缀，识别 HTML、文本与支持的文件格式 |
| Tavily / Exa 已返回正文，自动阅读仅复用 DeepSeek | 重复请求，增加耗时和失败机会 | 对正文标记原提供方与种类后统一复用 |
| content 字段也可能装摘要 | 直接复用会虚增正文成功数 | 区分正文、summary、snippet、highlights |
| Chromium 每次启动和关闭 | 重复启动耗时、内存峰值高 | 共享进程，每次读取使用独立 context |
| 多个 HTTP / feed 探测串行吃掉总预算 | 有效渲染来不及运行 | 分流、阶段上限、跳过低收益探测 |
| 首页和列表页一律用文章提取器 | 没有 article 主体便失败 | 结构化提取或自动阅读替补具体文章 |
| 内部阶段失败重复展示 | 恢复成功后仍满屏错误 | 一个操作归集 attempts，按最终结果显示 |

依据：[诊断报告](2026-11-16-task-trace-and-web-fetch-diagnosis.md)与[官方资料核验](web-fetch-provider-findings-2026-11-16.md)。生产日志中 12 次失败不是完整分母；7 条 JS_CHALLENGE 是程序标签，尚未逐页保留原始响应确认。

## 一个模块供两种入口共用

手动 read_url 和搜索自动阅读使用同一模块。调用方提交 URL、用途（当前 / 历史）、已有正文、截止时间、配置和取消信号；模块处理提取与恢复顺序。返回正文种类、内容、URL / finalUrl、来源、获取时间、可用的发布日期 / 快照时间、裁剪状态与 attempts。每个 attempt 保留阶段、引擎、结果、错误码、耗时。

现有 url-reader 导出保留为入口，HTML 调度移入内部模块，按 HTTP、提取、浏览器、缓存与提供方适配分别组织。保留既有工具入口、图片候选、PDF / DOCX / CSV 路径、重定向校验、响应体大小与取消契约。质量检查返回可解释的信号，不输出未经标定的成功概率。

### 1. 搜索正文先复用

Tavily raw_content、Exa text、DeepSeek 正文具有明确来源时进入质量检查。summary、snippet、highlights 保留其种类。合并搜索结果后仍保留正文的原提供方；不能仅凭 content 非空、或 sourceEngines 含某个引擎就认定是全文。既有 content 字段保留原含义，新增种类信息。

搜索且需要自动阅读时，按引擎能力请求正文，控制条数与长度；图片搜索继续原逻辑。正文开关与外部费用保持可见，不隐式开启新的付费提取。

### 2. 一次下载，多种提取

HTTP 下载后先处理语义正文和 JSON-LD Article 的 articleBody，再用现有 Readability。质量不足时将同一份 HTML 交给 Trafilatura，不重新下载。已经合格的正文不为追求更长结果而统一替换为噪声更多的内容。

正文质量结合页面类型、段落、导航占比、标题相关性、删除或登录提示与表格信息判定，避免固定英文词数误伤中文短新闻。首页、列表、行情表格可返回结构化内容，保留标题、链接和数值列；仅导航或空骨架才继续渲染。

### 3. Python 的职责与部署

首选 Trafilatura，默认去评论、按页面类型保留表格；初次提取不足时再提高召回。仅在具体样本证明必要时补 BeautifulSoup / lxml 结构规则，不同时安装多个重叠的爬虫框架。

推荐一个应用内常驻 Python 提取进程，初始并发 1。Node 传入请求 id、HTML 与最终 URL，返回正文、元数据、质量信号；日志使用 stderr。任务有大小与时间限制，取消或进程退出时结算对应请求并清理队列。

Python 提取器使用应用自有的锁定依赖，复用项目 Python 路径解析与构建能力，避免被 Skill 环境整理误删。依赖写进镜像构建和开发准备流程；只装在当前聊天环境不会更新 1Panel 容器。Python 缺失时明确记录能力状态并跳过此适配器，既有 Node 提取和浏览器仍可使用。

Python 提升的是非标准文章、表格与正文定位能力。403、JS 渲染和验证页由相应网络或浏览器路线处理，换语言本身不会改变响应内容。

### 4. 浏览器进程复用

每个 backend 进程共享一个 Chromium，默认一个并行 context、最多两个排队请求；空闲 15 秒回收。启动前与出队后检查 cgroup 内存限额和余量，低于预算跳过浏览器。每次读取独立 context，完成立即关闭；取消只关闭自己的 context。浏览器崩溃时结算在途任务，后续请求再建立进程，不无限重试当前 URL。

等待 DOM 与目标正文信号，避免统一等 networkidle 或固定多等几秒。保留脚本、XHR / fetch 和必要样式；在不影响正文与图片 URL 提取的前提下跳过视频、音频、字体等大资源。新增路线继续遵循项目既有导航与网络访问规则。

### 5. 总截止线内动态分流

保留手动读取默认 30 秒、自动读取单 URL 默认 18 秒的配置含义。HTTP 初始上限建议 5 秒；适用时 crawler 最多 3 秒；feed 仅使用页面声明的地址，总计最多 1.5 秒。启动下一阶段前检查剩余时间，优先保留有效后备阶段。

确认需要渲染时跳过 crawler 和猜测 feed。第三方提取与浏览器按失败类型选择，不能等浏览器耗尽总时限后再叠加长超时。既有 DeepSeek Fetch 继续仅在显式开启、有凭据且本地失败时参与，总截止线与费用开关不变。

自动搜索新增明确的批次 deadline，覆盖排队、替补和全部 URL，建议默认 18 秒。它与单 URL 超时分别存储和说明，不能重定义旧 autoReadTimeoutMs。默认目标两份有效证据，同时最多两条 URL；每批最多检查四个已返回候选，替补仅使用剩余时间。这项新增批次限制需单独验收。

### 6. 去重、短缓存与候选替补

同一运行内，同 URL、相同 freshness 和影响结果的配置共享在途工作。保留有语义的 query 参数，不为去重删除文章 id。一个订阅者取消只结束自己的等待，最后一个订阅者退出才终止共享任务。

跨运行只缓存可公开复用且无身份的内容；不跨 Cookie、身份或凭据域共享。初始缓存建议：普通公开文章 30 分钟、新闻 2–5 分钟；当前价格、行情、库存绕过普通文章缓存，使用满足时效的来源。429 遵循 Retry-After；失败结果仅短暂去重，不永久拉黑站点。

自动阅读中候选失败后，可在批次预算内换另一个高相关来源，保留原 URL 的真实结果；不反复整轮重搜。手动指定 URL 必须报告该页状态，不能换页后宣称原页读取成功。

### 7. 可选外部提取

优先已有搜索正文和本地能力。特定站点确有覆盖缺口时，再接管理员已配置且允许使用的 Tavily Extract / Exa Contents，Jina 可作为后续适配器。每 URL 每批至多一次额外提供方调用，受费用、总预算与并发限制。

Tavily 同时检查 results 与 failed_results；Exa 使用当前 maxAgeHours / livecrawlTimeout，保留 cached / crawled 等状态。删除 Google Cache；Wayback 仅用于明确历史用途，并返回 archivedAt。

## 少失败也要少干扰

一次读取保持一个 Tool Operation，内部尝试归入 attempts。阶段失败但最终取得正文时以成功结束，摘要显示已获取正文，详情保留恢复证据；仅有摘要显示仅取得摘要；最终无内容显示一次失败。

可恢复中间情况采用相应诊断日志级别，配置缺失、持续故障和最终失败继续准确记录。追踪保留 attempt 开始、结束、错误与总结果，聚合高频正文分片。不能仅改日志级别或把摘要计为正文来提高成功率。

追踪持久化、缺失状态与关键事件保留可以并行修复，不以重做日志 UI 阻塞正文读取改造。操作身份和恢复证据沿用 ADR-0044。

## 实施顺序和验收

| 批次 | 内容 | 验收依据 |
| --- | --- | --- |
| 第一批 | 误判、缺 MIME、完整配置传递、删除 Google Cache、正文来源与复用、阶段预算、关键 attempts | 正常文章与真实挑战分开；缺 MIME HTML 正确提取；摘要不冒充正文；取消与超时通过 |
| 第二批 | 共享 Chromium、候选替补、去重短缓存、Python 提取器 | 同 URL 不重复下载；context 隔离；Python 缺失或退出不破坏原有能力；恢复结果可追踪 |
| 第三批 | 按收益接外部提供方与少量结构规则 | 同环境、同样本正文覆盖改善，费用与时限受控 |

验证集从此次 12 条失败 URL 加已成功文章对照开始。实时结果与可重放 HTML 分开保存；算法回归以固定 fixture 判定，线上覆盖在同环境同样本下对比。

分别报告：去重读取 URL 数、有效正文数、结构化数据数、摘要数、最终无内容数、批次取得两份有效证据的比例、P50/P95 耗时、请求数、浏览器启动数、外部费用。attempt 数不当 URL 数，替补成功不反写原 URL 成功。没有实测前不承诺固定百分比覆盖。

接受标准是同一组样本取得更多真实内容，且请求和等待受控；不将摘要、历史快照、导航页计入正文。实现用项目测试命令验证，覆盖 Windows 开发和 Linux 镜像依赖。

沿用 ADR-0029 单镜像部署，Python 与浏览器是 backend 的受控依赖，不新增用户需在 1Panel 单独编排的容器。Skill 依赖规则保持既有含义。
