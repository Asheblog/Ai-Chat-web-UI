## 推荐结论

**先修设置的真实行为，再删除失效字段，最后收拢配置层级。** 当前复杂度主要来自失效输入、重复状态、暴露实现细节，以及模型参数缺少模型级适配。模型进步支持减少人工调参；它并未消除费用、权限、数据保留、上下文和自托管工具的选择。

审计阶段仅形成以下建议，分项报告保留当时的备选与证据；原始处置汇总见 [汇总清单](settings-decisions.csv)。这些建议已在 `settings-simplification` 实施，最终采纳范围、迁移和验收见 [实施与升级](implementation.md)。

## 第一优先：先修这些行为

| 问题 | 当前实际行为 | 推荐处理 |
| --- | --- | --- |
| **保留天数 0 与文案相反** | 图片保留 0 使用 `now - 1000ms` 截止线；匿名数据保留 ≤0 进入不按时间筛选的清理分支。界面均承诺“永久保留” | 令 0 真正跳过清理，保留此数据策略；与乱斗保留的 0 语义统一 |
| **设置保存失败仍报成功** | store 吞掉异常，卡片继续 toast“已保存”；已有 settings 时错误通常不展示 | 让失败结果返回调用方，只有成功才提示；补字段错误和重新读取有效值 |

| **知识库开关只接前端** | 开关控制 Web 可见性；对应 API 缺少这些功能/角色策略校验，其他认证检查仍存在 | 在服务端落实已声明的可用性与角色策略，再精简展示 |
| **模型覆写互相牵连** | 改访问策略/温度也置 `manualOverride=true`，能力刷新被跳过；“清除能力覆写”删整行，连权限/温度一起清掉 | 按能力、参数、访问策略拆覆写归属，重置只作用于所选部分 |

| `pythonToolMaxSourceChars` | 同上，旧值无消费者 | 同上 |
| `webSearchParallelMergeStrategy` | 三层解析恒为 `hybrid_score_v1` | 改实现常量，移除表单写入和持久化契约；搜索融合仍保留 |
| `assistantReplyHistoryLimit` | 用户明确取消回答版本上限：全版本保留、用量保留，无需手动删除版本功能 | 删除设置入口、共享契约与 `ensureVariantWindow` 裁剪；迁移删除该设置行；重新生成与版本切换沿用原入口 |

## 模型进步后，应换位置与默认策略的设置

| 设置 | 推荐 | 依据 |
| --- | --- | --- |
| 默认推理强度 `openaiReasoningEffort` | 主入口跟随模型；按模型裁剪选项与参数映射；全局仅作高级兜底，默认不显式发送 | OpenAI、Anthropic、Gemini、DeepSeek 的字段与等级不同。现有“请求 > 会话 > 系统 > 环境”回退有效，缺的是模型能力校验 |
| 默认温度 `temperatureDefault` | 保留模型级参数；全局降为高级回退 | 部分思考模式会忽略它，不代表所有模型都不需要。项目已支持模型温度 > 全局默认 |
| 默认生成 Tokens `reasoningMaxOutputTokensDefault` | 改名“默认生成上限”，从推理卡移走；默认自动按模型与协议解析，显式限制留高级 | 它实际是通用生成上限的三级兜底；某些接口要求明确上限，省略不等于使用厂商默认。Anthropic 适配层目前会补 4096 |
| `reasoningTagsMode` / 自定义标签 | 结构化推理优先；文本标签作为连接兼容高级项 | 官方协议已有结构化字段；私有与兼容模型仍可能输出标签，保留人工覆写 |
| 推理启用、展示、保存、协议回传 | 分清四层，减少一个开关同时改变多件事 | “不保存推理文本”与“后续工具调用是否必须带回协议字段”是不同要求 |
| 上下文压缩 | 保留开关，阈值和尾部消息数收高级 | 长上下文仍有费用、延迟与窗口限制；账户“不携带历史”是另一项选择 |
| 外部搜索、自托管 Python | 保留；厂商托管工具可作为按连接可选能力 | 托管执行地点、数据交付方式、检索策略和可用模型不同，无法等价覆盖现有工作区链路 |

官方依据：[OpenAI 推理类型](https://github.com/openai/openai-python/blob/main/src/openai/types/shared/reasoning_effort.py)、[Anthropic effort](https://platform.claude.com/docs/en/build-with-claude/effort.md)、[Gemini 内容与 thinking 类型](https://github.com/googleapis/python-genai/blob/main/google/genai/types.py)、[DeepSeek thinking](https://api-docs.deepseek.com/guides/thinking_mode)。精确观测、各模型限制和来源覆盖见 [官方证据报告](provider-evidence.md)。

OpenAI/Gemini 的部分官网页面抓取受限，参数事实采用官方 SDK/proto；没有据此宣称完整逐模型支持矩阵，也没有进行付费模型调用。

## 应收进高级区的内容

推荐将这些参数从默认展开层移走，保留有效控制：

- **网络与流式性能**：真实总体超时、首帧宽限、思考静默上限、SSE 心跳、分片大小与刷新节奏。
- **搜索执行参数**：并行引擎数、查询扩展数、批次时限、自动阅读并发。没有入口的 `webSearchAutoReadBatchTimeoutMs` 归高级/部署层，纠正文档“系统设置可调”的承诺。
- **RAG 调优**：Embedding 批量/并发、分块大小/重叠；主层保留模型选择、文件限制、召回效果和数据策略。
- **上下文压缩**：触发比例和尾部保留条数。
- **品牌配色**：6 个颜色 Token 收到一个高级配色组，品牌名与头像留主层；说明部分颜色仅对浅色生效。
- **用量事件**：`usageEmit` / `usageProviderOnly` 转为内部协议策略，保留用量展示、来源与估算标记。缺推理明细降低分项解释能力，不直接等于总消耗被低估。

CSV 的“高级 21”统计整行归高级的共享字段，不包含上面兼有修复或合并标签的字段。用户真正需要选择的 Key、访问范围、费用额度、数据保留、并发资源上限和工具权限仍保留。

## 推荐的信息结构

系统主导航由现在 10 个叶子收敛为 **6 组**：

1. **连接与模型**：连接、凭据、模型目录、模型生成参数与能力覆写。
2. **搜索与知识库**：搜索引擎、知识库、Embedding 与文档管理。
3. **工具与扩展**：MCP、Skills、Python 与扩展安装权限。
4. **用户与访问**：注册审批、模型访问、额度与用户管理。
5. **数据与日志**：保留策略、上下文压缩、并发、系统日志与任务追踪；网络性能放高级。
6. **外观与站点**：品牌名、头像、主题与公开访问 URL。全局系统提示词归对话/模型配置，不放品牌配色卡。

概览作为入口顶部状态摘要，去掉“开放注册、开启搜索才算完成”的完成率。私有且离线的部署同样完整可用；模型列表非空也不等于已经设置默认模型。日志查看保留可达路由，避免设置与独立日志入口重复配置。

## 分批实施与验收

| 顺序 | 交付范围 | 迁移 / 验收重点 |
| --- | --- | --- |
| **第一批：修正确性** | 0 保留语义、失败提示、默认值统一、安装开关、知识库服务端策略、模型重置边界、回答版本全保留与用量不回退 | 使用隔离数据验证 0 不删、失败不报成功、开关读写生效、能力重置不清访问策略、超过原上限的版本与其 `usageMetric` 都保留 |
| **第二批：删死项、合重复** | 前述 6 个共享字段、连接伪选项、引擎顺序/双语、能力双入口、追踪有效状态、标题选择器 | 同步删除前后端契约与过时文档；一次性归并旧值；导入导出版本与存量连接有明确迁移 |
| **第三批：重组与模型适配** | 6 组导航、高级折叠、模型参数裁剪、结构化推理优先、保活合并 | 验证支持模型/兼容模型、原参数优先级、反代长流及设置错误态；产品 UI 调整再做真实页面验收 |

合并字段不保留两套长期可写真源。保留策略、访问控制和认证项切换前明确旧值如何解释。日志和任务追踪“保留天数”目前主要服务手动清理：推荐在后续实现中接入现有应用清理生命周期；在这之前文案应明确“立即清理使用此阈值”。

另有适合随批修正的小问题：搜索范围被错误绑定为仅 Metaso 可见；文件上传前端写死 100MB 而后端默认 50MB；启用引擎未配 Key 会被运行时静默跳过；额度和系统提示词优先级文案与实现不同。逐点见分项表，不另扩展产品能力。

## 对最初“单条消息 AI 回答上限”的最终决定

**取消该上限（用户最终决定）。** 回答版本全部保留：同一用户消息下的历史回答不再按条数删除，重新生成与版本切换继续使用原入口；版本正文与其 `usageMetric` 一起保留，会话总量、会话列表和每日汇总不再因版本裁剪回退。**不需要新增“手动删除某个版本”的功能**——本条要求是保留全部版本，不是换一种删除方式。

实施内容：删除设置入口与共享契约字段 `assistantReplyHistoryLimit`、删除 `ensureVariantWindow` 的删除分支（只保留 `variantIndex` 重排，维持选择/重新生成语义），迁移清理存量 `assistant_reply_history_limit` 行。证据与验收见 [设置精简实施与升级](implementation.md) 与 [P0-2 最终决定](system-settings.md#L149)。

基线审计当时曾建议“暂保现值、先解耦版本保留与用量”，原因是当时只删入口会同时留下删除行为并静默作废已配置值；该建议已被上述最终决定覆盖，保留在 [system-settings.md](system-settings.md) 仅作原始判断记录。回答版本属于存储与数据生命周期策略，但用户明确以“全保留”取代“可调上限”。
